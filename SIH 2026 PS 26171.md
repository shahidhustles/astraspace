# **SIH Problem Statement 26171**

## **On-device Visual Perception for Light-weight Browser Agents**

## **1\. Problem understanding**

The problem is about building a privacy-first browser agent.

Current AI browser agents need access to:

* Screenshots  
* DOM structure  
* Current webpage context  
* User workflows

However, sending raw browser data to cloud models can expose:

* Passwords  
* Personal information  
* Private documents  
* Account details  
* Faces  
* Confidential page content

The solution is a local privacy layer that runs before any external model request.

The core flow:

Browser  
   ↓  
Local perception layer  
   ↓  
Sensitive information detection  
   ↓  
Local sanitization/redaction  
   ↓  
Cloud or on-prem AI model  
   ↓  
Browser actions  
   ↓  
Repeat

The browser agent can still use powerful reasoning models while ensuring sensitive information is filtered before leaving the user's machine.

# **2\. Core client-side features**

## **Local visual perception**

The browser client will locally understand the current screen state.

Capabilities:

* Screenshot capture  
* UI element understanding  
* Visible content extraction  
* Local vision model inference  
* Screen-state analysis

Possible technologies:

* WebGPU  
* WebAssembly  
* ONNX Runtime Web  
* Transformers.js

The system should prefer lightweight models that can run inside the browser runtime.

---

## **DOM understanding and page structure extraction**

The agent should not depend only on screenshots.

The extension will inspect webpage structure:

* Inputs  
* Buttons  
* Forms  
* Labels  
* Accessibility information  
* Visible text  
* Element coordinates

DOM information helps detect sensitive fields without requiring expensive vision inference.

Example:

\<input type="password"\>

↓

Sensitive field detected:  
PASSWORD  
Bounding box:  
(x,y,width,height)

* Autocomplete metadata

Detection methods:

Supported examples:

* Names

## **Vision-based PII detection**

Examples:

* OCR  
* Face detection  
* Lightweight vision models

# **4\. Redaction methods**

The system supports multiple privacy strategies.

## **Bounding box redaction**

Completely hides sensitive regions.

Example:

Password: █████████

Useful for:

* Passwords  
* Tokens  
* Secrets

---

## **Masking**

Partially hides information.

Example:

Card number:  
XXXX XXXX XXXX 4242

Used only when partial information helps the task.

---

## **Semantic redaction**

Replace private information with meaningful placeholders.

Example:

Before:

John Smith  
john@gmail.com

After:

\[PERSON\_1\]  
\[EMAIL\_1\]

The AI understands the role of the information without seeing the actual value.

---

# **5\. Sanitized context sent to AI**

The model should not receive raw browser data.

Instead it receives:

## **Sanitized screenshot**

Example:

Email: \[PRIVATE EMAIL\]

Password: \[PRIVATE PASSWORD\]

Button:  
Submit  
---

## **Sanitized page representation**

Instead of sending raw HTML:

\<input value="secret"\>

send:

Textbox:  
Role \= Password  
Value \= \[PRIVATE\]

Button:  
Submit

This reduces:

* Privacy risk  
* Token usage  
* Latency

---

## **Redaction metadata**

The model receives information about what was removed.

Example:

{  
  "type": "EMAIL",  
  "location": \[120,50,200,30\],  
  "confidence": 0.98  
}

The original value never leaves the device.

# **8\. Agent intelligence features**

Beyond the base PS requirements, the browser agent will include advanced agent capabilities.

## **Memory system**

The agent will have three memory layers.

## **Session memory**

Temporary context during the current interaction.

Stores:

* Current task  
* Current page state  
* Recent actions  
* Current conversation context

Example:

User asked:  
"Fill this form"

Agent remembers:  
Already completed step 1  
Currently on step 2  
---

## **Episodic memory**

Stores past experiences and workflows.

Examples:

* Previous tasks completed  
* User workflows  
* Common actions  
* Past browser sessions

Example:

Last month:  
User created similar reports using this workflow.  
---

## **Semantic memory**

Long-term knowledge storage.

Stores:

* User preferences  
* Important facts  
* Frequently used information  
* Domain knowledge

Example:

User prefers PDF reports  
User usually works with Google Drive documents  
---

# **15\. Future challenge**

MCP tool outputs will initially be passed to the model as-is. Once the MCP layer is ready, MCP content redaction will become a separate challenge because removing sensitive information from connected tools without breaking the usefulness of the data requires a different approach.
